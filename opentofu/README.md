# OpenTofu external-resource scaffold

This root module is intentionally a zero-resource, Cloudflare-provider-only
scaffold. OpenTofu `1.12.5` and `cloudflare/cloudflare` `5.23.0` are exact reviewed
pins. The local backend points to the Ansible-managed operator directory on the
Debian host, outside k3s and every Kubernetes volume.

The current increment authorizes only the pinned CLI installation and this source.
It does not authorize or run provider initialization, provider download,
configuration validation, planning, apply, import, state commands, destroy, a
Cloudflare API request, or any Kubernetes operation. Before initialization, an
authoritative reviewed checkout at the exact approved revision must be placed on
the Debian host and every OpenTofu command must run as the exact non-root operator
selected by the Ansible installer. Checkout transport, authentication, revision
verification, and the server working path are unresolved and therefore block
initialization.

The dependency lock file must be generated by a later separately approved
initialization and must never be hand-authored. That future initialization also
creates ignored `.terraform/` backend metadata and downloads provider code; it is
not a lockfile-only operation. All those effects require review at that later gate.

Provider authentication will be ephemeral and environment-supplied after its own
least-privilege review. Credentials, account or zone identifiers, state, plans,
variable files, and credential-bearing examples do not belong in Git. This module
must not gain a Kubernetes, Helm, GitHub, local-exec, or remote-exec provider or
provisioner. It creates no Tunnel, DNS record, hostname, route, or other public
exposure.

The local backend has only host-local single-process locking and remains a
single-node failure domain. Before the first provider-backed plan or apply, the
operator must implement and rehearse encrypted timestamped off-node copies to
Google Drive, independent encryption-key recovery, integrity verification, and
state restoration. Copies use non-destructive append-only semantics, never blind
synchronization. Until that evidence exists, state recovery is `UNKNOWN — STOP` and
no apply is permitted.
