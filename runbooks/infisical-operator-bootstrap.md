# Infisical Cloud Kubernetes Operator bootstrap

## Boundary

This runbook installs only the Infisical Kubernetes Operator client and its separate
authenticated egress proxy. Infisical Cloud remains the server and value owner. No
self-hosted Infisical server, database, PVC, public Service, route, PROD scope, or
credential value exists in committed source.

The guarded source contains exactly 40 objects:

- six complete namespaced CRDs promoted from chart `0.11.7` with SHA-256 mapping;
- six fail-closed ValidatingAdmissionPolicies and six bindings;
- two ServiceAccounts, four Roles, and four RoleBindings;
- one Squid ConfigMap, one ClusterIP Service, and one proxy Deployment;
- one Operator Deployment; and
- eight NetworkPolicies.

`MANIFESTS.sha256` and the action-plugin canonical object map bind the complete
closure. ClusterGenerator, Secrets, ClusterRoles, ClusterRoleBindings, metrics
Services, ServiceMonitors, Ingress, routes, PVCs, and PROD objects are absent.

## Required proxy secret-zero inputs

The install wrapper refuses check and apply until these exact metadata contracts
exist in `shared-services`:

| Secret | Type | Exact keys | Owner |
|---|---|---|---|
| `infisical-egress-proxy-tls` | `kubernetes.io/tls` | `ca.crt`, `tls.crt`, `tls.key` | temporary secret-zero writer |
| `infisical-egress-proxy-auth` | `Opaque` | `users` | temporary secret-zero writer |
| `infisical-egress-proxy-client` | `Opaque` | `proxy-url` | temporary secret-zero writer |

The client URL is an HTTPS proxy URL whose user information carries the matching
Basic credential. The certificate must validate for
`infisical-egress-proxy.shared-services.svc`. The NCSA file and URL are two
representations of one credential and rotate together. Values are generated by a
separate no-log/no-diff controller procedure and encrypted with `age`. Only the
ciphertext and its checksum cross to the k3s host, where the pinned host rclone
performs an immutable Google Drive copy and readback. The controller then decrypts
that readback with the separately held age identity. Git, the host, Drive, CLI
arguments, Ansible diff, and retained evidence must never contain plaintext proxy
values or the age identity.

The proxy secret-zero writer is intentionally separate from Infisical Cloud because
using Infisical to retrieve the credential needed to reach Infisical is circular.
The exact flow is defined by the
[guarded host rclone runbook](rclone-host-transfer.md). The pinned installer places
rclone `1.71.1` on the host; OAuth is created interactively only in the non-root host
operator's mode-0600 config. `transfer-infisical-proxy-recovery` stages only the
existing encrypted pending archive/checksum, performs immutable host-side upload and
readback, fetches only encrypted readback, and creates `drive-verified` after
controller decrypt and relationship validation. Only then may
`bootstrap-infisical-proxy-secrets apply` write the exact three Secrets through its
guarded no-log/no-diff action. The age identity never reaches the host or Drive; it
remains in the user's mode-0700 controller application-support directory and
protected macOS login Keychain. Failure preserves the encrypted pending bundle and
removes controller plaintext temp files. A completed marker prevents implicit
rotation. The three Secrets are not evidence that Universal Auth or any application
value has been bootstrapped.

## Source and admission behavior

The Operator runs in `shared-services`, watches exactly `shared-services`, `argocd`,
and `cristexhub-dev`, and excludes PROD. Metrics bind to `0`; no metrics Service or
authorization exists. The single ServiceAccount receives only three namespaced
manager Roles and one leader-election Role. TokenReview, SubjectAccessReview,
service-account token creation, aggregate user roles, manager cluster access,
ClusterGenerator, workload reload, Secret mutation, and ConfigMap mutation are absent
from this idle closure. The separate non-sensitive proof must add only its required
`cristexhub-dev` target permissions after its exact source is reviewed.

The six admission policies use `failurePolicy: Fail` and `Deny` on CREATE/UPDATE.
They require Universal Auth, exact or default `https://app.infisical.com/api`, and
same-Namespace connection, credential, source, target, and TLS references. Push
Secret generators are rejected. Status and finalizer updates remain permitted when
the unchanged spec satisfies the same rules. A denied cross-Namespace fixture is a
required live acceptance check before any custom resource is created.

## Proxy and NetworkPolicy behavior

Squid is a separate tokenless pod pinned to Canonical's linux/amd64 manifest digest.
It terminates only the TLS connection for the explicit proxy protocol; it never
intercepts the tunneled Infisical TLS session. Ordered ACLs require authentication,
CONNECT, exact `app.infisical.com`, port 443, and a public resolved destination, then
deny all.

The Operator explicitly overrides the in-cluster API host with
`kubernetes.default.svc` and bypasses the proxy only for Kubernetes service DNS names
and loopback. NetworkPolicy allows Operator DNS, the policy-bound Kubernetes API
Service on TCP 443, and the proxy pod on TCP 3129. It has no general Internet 443
rule. The proxy accepts only the Operator, resolves only through CoreDNS, and may
reach public TCP 443 excluding private and special IPv4 ranges. Squid provides the
hostname/CONNECT enforcement that standard NetworkPolicy cannot express.

The committed API Service `/32` is target-bound. The wrapper verifies the live
`default/kubernetes` Service address before any mutation and stops on replacement
cluster drift. Replacement recovery must regenerate and review this one policy rather
than silently broadening it.

## Guarded sequence

Only the repository entrypoints and explicit OAuth gate are authorized, in this
order:

```text
ansible/bin/install-rclone check
ansible/bin/install-rclone apply
# interactive host OAuth as the inventory-selected non-root operator
ansible/bin/transfer-infisical-proxy-recovery check
ansible/bin/transfer-infisical-proxy-recovery apply
ansible/bin/bootstrap-infisical-proxy-secrets apply
ansible/bin/bootstrap-infisical-operator check
ansible/bin/bootstrap-infisical-operator apply
```

Install, OAuth, transfer, Secret write, Operator check, and Operator apply are distinct
approval boundaries. Transfer check validates metadata and the configured Google
Drive backend locally without network access or writes; approved transfer apply
performs OAuth preflight and may refresh only the protected host config. The Secret
writer has no check mode because generated
values cannot be meaningfully predicted; it refuses diff mode and requires the exact
mode-0600 `drive-verified` marker before Kubernetes contact.

The wrapper accepts exactly one mode, supplies every Ansible argument, starts the
pinned controller under a clean environment, creates a mode-0600 one-run attestation,
and uses the exact inventory, host limit, diff mode, and present-only approval. It
uses established `k3s-admin` group access and does not request or store sudo. Direct
playbook use, passthrough arguments, tags, skip-tags, step mode, or start-at-task are
forbidden. The action plugin rechecks task selection and the canonical hash of every
object at the mutation boundary.

Check performs preflight and predicts exact changes but requires the real proxy Secret
metadata; it never creates a placeholder. First apply installs CRDs, waits for
Established, then applies only the remaining 34 objects and waits for both Deployments
to become Available. Idempotence is a separate invocation and must finish with
`changed=0`.

The separate source-only
[Universal Auth/value lane](infisical-universal-auth-value-lane.md) is a future
secret-zero prerequisite, not part of this idle closure. It seeds exactly three
same-Namespace runtime credential Secrets and uploads exact bootstrap values only
through its own apply-only protected entrypoints. Its out-of-band identities,
project, protected recovery, API compatibility, seed, upload, and rotation evidence
remain **NOT RUN/BLOCKED**. Do not run this Operator wrapper before the three proxy
Secrets and its independent runtime gates are approved.

## Required acceptance evidence

1. Host rclone install check/apply/idempotence proves the exact version, digests,
   paths, ownership, and unchanged k3s/Tailscale; host OAuth and encrypted transfer
   prove immutable Drive upload/readback and exact controller decrypt without moving
   the age identity or plaintext to the host.
2. Check predicts only the 40 Operator source objects and mutates nothing.
3. Six CRDs are Established with exact served/storage versions; ClusterGenerator is
   absent.
4. Six policies and bindings are admitted without warnings; same-Namespace positive
   dry-runs and cross-Namespace/generator/alternate-auth negatives behave exactly.
5. Both Deployments are Available with observed image IDs matching the selected
   linux/amd64 digests, no restart loop, and no unexpected Secret or Service.
6. Controller Lease acquisition works without forbidden RBAC. Negative authorization
   checks prove no cluster RBAC, review/token, workload, Namespace, CRD mutation, or
   Secret write privilege.
7. Operator DNS/API/proxy flows succeed. Direct public 443, proxy use by unrelated
   pods, unauthenticated/wrong-auth proxy use, wrong host/port, IP literal, and private
   destinations fail.
8. k3s and Tailscale remain running; all four Namespace UIDs/labels/phases remain
   unchanged.
9. A second apply returns `changed=0` and the exact inventory/writers remain stable.
10. Only afterward may the separate Universal Auth/value lane recover/write the
   three namespace-local runtime credentials, followed by an independently reviewed
   non-sensitive DEV ConfigMap proof; neither procedure is authorized by this source.

## Stop and rollback

Stop on any missing recovery artifact, Secret disclosure, unexpected object or writer,
CRD warning, VAP rejection of controller status/finalizer updates, public/open proxy,
direct Operator Internet egress, unexpected metrics endpoint, broadened RBAC, image
mismatch, workload restart loop, Namespace drift, or k3s/Tailscale degradation.

Rollback never deletes a Namespace, CRD, bootstrap Secret, or generated value.
Before runtime it is Git revert. After runtime, preserve the API/storage objects and
use a separately reviewed exact workload stop; investigate before retrying. Never
respond to a failure by granting wildcard RBAC, allowing general 443, disabling
admission, adding ClusterGenerator, or sharing identities.
